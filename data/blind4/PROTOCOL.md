# Fourth independent PDF audit

Pre-registered before selection or parsing. It measures the code after the systemic verification pass of November 22 (docs/EVALUATION.md), which was developed on the three spent blind sets and the controlled error-injection set. Code and this protocol are committed before running `pick-blind4.py`; the manifest records that commit. No core change until the run and its reviews are complete, and no change made because of this set may be reported as part of its result.

- Selection: the same rule as set 3 (`pick-blind4.py`): for each of 12 arXiv categories never used by development papers, the parser corpus or sets 1–3 (cs.MA, cs.GT, cs.IT, cs.GR, astro-ph.EP, cond-mat.supr-con, hep-lat, nucl-ex, math.DS, q-bio.CB, physics.med-ph, physics.app-ph), the newest primary-category article with a downloadable PDF and at least 10 entries in its source .bbl; plus the two newest eligible PLOS ONE research articles, counted from JATS. Every previously downloaded arXiv paper is excluded. Rejected candidates and reasons are recorded. The parser plays no part in selection; extraction failures stay in the denominator with zero verified references.
- Freeze and run: full git commit, clean source, query time, fixed PDF version/URL. One empty in-memory cache, papers sequentially, six reference workers, 40-second per-reference budget, and the browser's sequential second pass for 1–30 references left unchecked (30 s each), so the run matches what a user of the web app sees. No paid keys or quota. Start only after OpenAlex's response headers show a positive free allowance; record any later exhaustion. Results are never overwritten and the run is not repeated.
- Review: every flag against the PDF and the publisher/identifier record: real error / false alarm / uncertain, with a source URL and explanation. Minor cosmetic differences are false alarms. Three randomly selected verified references per paper for missed errors; five references per paper sampled independently of verdict for segmentation and field correctness against the PDF (pass/fail/N/A).
- Report: false alarms / all extracted references, flag precision (uncertain kept in the denominator), verified coverage, unverifiable and unchecked shares, count completeness against the .bbl/JATS truth, excess entries, time per paper (median and range), host failures. Compare coverage and abstention with sets 1–3; a lower false-alarm rate obtained through lower coverage is not a pass.
- Targets: false alarms / all references ≤2%, count completeness ≥95%, coverage not below set 3 (81.1%). The development rates on the spent sets (about 1.0–1.5%) were measured on papers the rules were written against; this set tests whether they generalise.
